## 1. PPO vs Expert（短/中/長）

執行：
```
python scripts/train_ppo.py --model models/bc_v3.pt \
  --updates 2000 --curriculum 0 --kl_coef 0.0 --lr 3e-5 \
  --ent_coef 0.02 --eval_every 20 --save_every_eval \
  --out_dir models/ppo_v13_long_vs_expert
```

輸出：`models/ppo_v13_long_vs_expert/ppo_u{0020..2000}.pt`, `ppo_best.pt`, `ppo_final.pt`

### 短中長對比（外部 eval seed=11111, n=300）

| 階段 | Checkpoint | 整體勝率 | 變化 |
|---|---|---|---|
| baseline | bc_v3 | 51.3% | — |
| **短** | u0100 | 52.7% | +1.4 |
| **中** | u0500 | 56.3% | +5.0 |
| (中後) | u1000 | 56.7% | +5.4 |
| **長** | u2000 | **61.0%** | **+9.7** |
| 訓練最佳 | best (u0900) | 60.3% | +9.0 |

**結論：跟 expert 對打，訓練越久越好**。從 u100 → u2000 線性上升，沒有 plateau 跡象。如果繼續到 u3000-u5000 可能還能再爬一點。

## 2. PPO Self-play（短/中/長）

執行：
```
python scripts/train_ppo.py --model models/bc_v3.pt --self_play \
  --updates 2000 --curriculum 0 --kl_coef 0.0 \
  --snapshot_every 30 --pool_size 10 --qual_games 15 --qual_threshold 0.50 \
  --eval_every 20 --save_every_eval \
  --out_dir models/ppo_v13_long_selfplay
```

每 30 個 update 拿當前 model 跟 pool 對打 15 局，超過 50% 勝率才加入 pool。Pool 容量 10。

### 短中長對比（外部 eval seed=11111, n=300）

| 階段 | Checkpoint | 整體勝率 | 變化 |
|---|---|---|---|
| baseline | bc_v3 | 50.3% | — |
| **短** | u0100 | 55.3% | +5.0 |
| **中** | u0500 | 50.0% | **0**（退回 BC 水準！）|
| (中後) | u1000 | 57.3% | +7.0 |
| **長** | u2000 | **58.0%** | **+7.7** |
| 訓練最佳 | best (u1500) | 54.0% | +3.7 |

**結論**：
- Self-play **U 形**：短可以、中崩、長回穩
- u500 整體 50%，**完全退回 BC 水準**。end-spam 飆到 10.8%（模型學會了拖時間）
- u2000 也只有 58%，比 vs-expert u2000 (61%) 差 3%
- Pool 機制有運作（最後 pool 滿 10 個），但 entropy 在 u500 後維持在 ~1.0（vs vs-expert 0.5-0.7），代表模型一直很雜亂
- 訓練 eval 報的 69% (u1500) 跟外部 eval 54% 落差 15%，**self-play 的 best checkpoint 不可靠**

**Self-play 不適合這個任務**：對手池都是同一條訓練線的早期版本，缺乏 expert 那種多樣策略的訊號。

## 3. BC with 岩漿地形

修改：`trpg/rl/env_v2.py` 的 `LAYOUTS` 多塞一個 "lava"：
```python
LAYOUTS = ("open", "open", "walls", "difficult", "lava")
```
`_apply_layout("lava")` 本來就有，在中間放一個 3m×3m DANGEROUS terrain。

執行：
```
python scripts/train_bc.py --episodes 50 --epochs 20 \
  --out models/bc_v4_lava.pt
```

| 模型 | 隨機 layout | lava layout only |
|---|---|---|
| bc_v3 | 43% | 41% |
| bc_v4_lava | 41% | 41% |

**結論**：加岩漿地形訓練，整體勝率沒變、lava layout 上也沒進步。
原因：scripted expert 自己**不會避開**岩漿（pathfinding 只繞 wall 不繞 dangerous），所以 BC 學不到「繞開岩漿」的行為。

要看到模型避開岩漿，需要先改 `combat_policy._move_to`，讓 expert 自己會避 dangerous terrain。

## 4. 嘗試提升 — 加更多 BC 資料

### bc_v5_long: 100 ep × 30 epochs（vs bc_v3 的 50 ep × 20 epochs）

| | bc_v3 | bc_v5_long |
|---|---|---|
| 整體勝率 | 51% | 50% |
| end-spam rate | 0.7% | **15.9%** ← 大幅修復 |

加倍資料**沒讓整體勝率上升**，但 **end-turn collapse 被部分修復**（從 0% 升到 16%）。
end-turn 是長期未解的問題，這次第一次看到實質改善。

### bc_v6_huge: 200 ep × 30 epochs（4x bc_v3 資料）

| | bc_v3 | bc_v5_long | bc_v6_huge |
|---|---|---|---|
| 整體勝率 | 51% | 50% | **44%** ← 退步！|
| end-spam rate | 0.7% | 15.9% | 11.7% |

200 ep 反而**退步**。原因推測：
- 200 ep 把資料增廣到包含更多「expert 自己也輸的局面」
- 模型把這些局面當正例學，反而學到 expert 在劣勢下的 panic 行為
- 或單純 overfit

**Sweet spot 在 100 ep（bc_v5_long）**，再加沒幫助。

### PPO from bc_v5_long (`models/ppo_v14_bcv5`)
```
python scripts/train_ppo.py --model models/bc_v5_long.pt \
  --updates 1000 --curriculum 0 (rest same)
```
| | bc_v5_long | ppo_v14_bcv5 final |
|---|---|---|
| 勝率 | 50% | **58%** |

### PPO from bc_v6_huge (`models/ppo_v15_bcv6`)
```
python scripts/train_ppo.py --model models/bc_v6_huge.pt \
  --updates 1000 --curriculum 0
```
| | bc_v6_huge | ppo_v15_bcv6 best |
|---|---|---|
| 勝率 | 44% | **60%** |

**重點**：不管 BC base 是 51%、50% 還是 44%，PPO 後都收斂到 58-60%。**任務上限大約在 60-61%**。

## 推薦的下一步

如果還想推勝率：
- **arcane_trickster / assassin / war 是大坑**（PPO 拉不動）。可能要加 DAGGER（用 model 自己跑、expert 標）才能補 state distribution。
- 加 `kl_coef=0.05` 配 PPO，避免 PPO 飄掉 BC 已經學會的能力（特別是 vow_of_enmity 這種「先 BC 學會、PPO 反而忘掉」的）
- 改 `_move_to` 讓 expert 路徑規劃避開 DANGEROUS，讓 BC 真的學到岩漿應對

如果想換方向：
- 60% 已經是這個 archetype 集合的合理上限（vengeance 83% 是天花板，arcane_trickster 0-16% 是地板，整體平均不可能太高）
- 想再上一層需要重新檢視 scripted expert 自己的勝率 — 如果 expert vs expert 不到 80%，模型不可能超過 expert
