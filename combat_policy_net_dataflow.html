CombatPolicyNet 的資料流動

一張盲眼統一策略網:一路編碼 → 128 維共享主幹 h → 四個階層式頭 (end → skill →(entity｜grid))。琥珀色是 forward() 當場算出、拼進頭的額外輸入。技能組身分用 codeword(skill_combo_dim) 以加法雙線性項餵進 skill 頭;免疫/抗性沒有任何手寫特徵——全靠 sk_ent_ctx 這條學習注意力,從實體描述子把抗性讀出來。所有形狀從現行網 (CombatPolicyNet(n_head_groups=1, skill_combo_dim=8))實測。

02 · Encoder 四路並行編碼(_encode)

skill_proj + encoder Linear→Transformer

66→64 投影,再過 2 層 TransformerEncoder(d=64, 4 head, ff=128), padding 槽遮罩。masked-mean → sk_mean。

out sk_emb [B,20,64] · sk_mean [B,64]

entity_mlp MLP 121→64→32

每列共享 MLP。取 slot 0 → self_emb。

out ent_emb [B,10,32] · self_emb [B,32]

無 CNN、不做全域池化。位置經「自我索引讀取」進入 h(取 slot 0、取自己那格), 平均池化會把位置稀釋成 1/900。抗性/免疫描述子也在這裡壓進 ent_emb → 是 sk_ent_ctx 讀免疫的唯一來源。

spatial gather cat + gather

9 通道疊成 spatial_feat [B,9,30,30]; 在自己所在格取一根 → self_cell_feat。

out self_cell_feat [B,9]

res_mlp Linear 4→16

資源向量小 MLP。

out res_ctx [B,16]
concat → [B, 130]▼

03 · Trunk + FiLM 共享主幹表徵 h

trunk Linear 130→128→128 (ReLU)  ·  FiLM 調變

sk_mean64 + self_emb32 + self_cell_feat9 + res_ctx16 + decision_ctx9 = 130 → trunk → h [B,128]

FiLM: 由自身 archetype one-hot(12 維)產生 per-archetype 的 γ, β,做 h ← γ·h + β。初始化為恆等(γ=1, β=0)。 這條 h 只餵進 grid 頭——在 skill / entity 頭裡 h 對選擇是逐槽常數、 會被 softmax 消掉(死權重),已移除;end 頭本來就不吃 h。

h [B,128] + raw obs▼

04 · Head-side extras 頭的額外輸入(forward 現算)

sk_ent_ctx cross-attention · 1 個學習投影

技能→實體注意力:每招用 query=proj(sk_emb) 去挑「跟我這招相關的單位」, 遮掉不存在的槽 → 讓 skill 頭條件化於 per-entity 狀態。學習權重 skill_ent_attn_proj(64→32)。

[B,20,32]

免疫/抗性的唯一通路。抗性描述子(I_DESC_RESIST)已在 entity_mlp 壓進 ent_emb, 這條注意力把它 soft-attend 進來 → 模型可據此逐局讀出敵人對哪型免疫、選對傷害型 (2026-07-06 隔離實驗證:單靠這條就能從零學會)。

blocked_feat scale × sk_emb

blockedness × sk_emb → [B,20,64]。 blockedness = 1 − 自身格視線近接度。開闊地視線=1 → 此項恆為 0。

只在被牆擋住時非零 → 練它只改被擋時的選招,開闊/團隊戰位元級不變。

05 · Heads 四個階層式頭 · 每個頭的輸入拼接(顏色＝來源類型)

讀法:chip 上的數字是每一個技能槽/每一對的特徵寬度(相加＝拼接後的寬度), 技能槽數 20 是另一條軸——頭對每個槽各跑一次、20 這軸保留成輸出長度。 例:skill_head 的輸入其實是 [B,20,160],Linear 160→1 把最後一軸壓成 1 → [B,20]。主幹 h 不在 skill / entity 頭裡——它對每個槽都一樣、 在 softmax 會被消掉,所以移除(見下方 skill_head 說明);h 仍進 grid 頭。

end_head MLP 22→32→1

結束 vs 繼續。與主幹 h 解耦——只讀手挑的標量。

end_features20 + self_threat1 + self_reach1 = 22 → end_logit [B]

解耦是為了堵「輸棋時梯度沿 end 方向漂移逼模型提早結束」;threat/reach 兩旗讓「安全就停止風箏」「打不到又滿血就結束保留治療」有依據。

skill_head Linear 160→1 · per-group gather

每個技能槽一個 logit。不含 h(逐槽常數、softmax 消掉)。

sk_emb64 + sk_ent_ctx32 + blocked_feat64 = 160 → skill_logits [B,20]

+ codeword(技能組身分,加法雙線性項,不進 concat): skill_combo_proj(sk_emb) [B,20,8] 對持有的技能 masked-mean-pool → 身分 c [B,8];skill_combo_pref(c) → pref [B,64]; skill_logits += ⟨sk_emb, pref⟩(per-skill)。這正是為何 h 被移除、codeword 被加入: h 對每個槽相同、在 softmax/argmax 會被消掉動不了選擇(實測歸零 h 欄,選招 softmax 差 <1e-7); 身分訊號必須用這種逐招不同的乘法項才推得動選招。

entity_head Linear 96→1 · per (skill,entity)

給目標選擇——每個(技能,實體)對一個分數。不含 h (h 對某招下的各實體也是常數、在 per-skill 選目標 softmax 消掉)。

sk_emb64 + ent_emb32 = 96 → entity_logits [B,20,10]

導向抗性敵/脆弱敵的判斷走 ent_emb(內含抗性描述子)—— 和 sk_ent_ctx 同源,不再有手寫的 per-pair 免疫欄。

grid_head query 192→9 · bmm

每技能一個 grid_query,與 spatial_feat 做點積 → 每格分數。取代 CNN:距離已預算成通道,只需線性打分。

sk_emb64 + h128 = 192 → query [B,20,9] ⨯ spatial[B,9,900] → grid_logits [B,20,900]

唯一保留 h 的頭。這裡 h 進 query、再與每格不同的 spatial 特徵點積 → h·spatial[cell] 逐格不同,不是常數,真的會影響落點選擇(故不移除)。

critic MLP 1309→128→128→1

獨立價值網,自己的權重、自己的簡易編碼器——與策略完全解耦。 價值 MSE 不會擾動策略表徵。

entities_flat1210 + resources4 + end_features20 + skill_pool66 + decision_ctx9

= 1309 → V(s) [B]

skill_pool(可用技能特徵的遮罩平均)讓 critic 分得出「大招/戰技骰還在」與「已用掉」, 否則 PPO advantage 偏誤會把近戰連招職業推離攻擊。

06 · Action 階層式動作組裝 + 決策層遮罩

end → skill →(entity ｜ grid)

σ(end_logit) > 0.5 → 結束本子回合。否則從 skill_logits 選技能; 再依該技能的 target_type 走 entity 頭(打單體/治療)或 grid 頭(POINT/LINE/CONE 落點)。 per-skill 條件結構鏡射引擎的動作語義,治好了舊版共享頭「grid 塌到 cell 0、entity 塌到 self」的聯合-邊際問題。

取樣之前,apply_resource_mask / apply_entity_mask 先遮掉引擎會拒絕或效果為 null 的招/目標:資源不足、射程外、無視線、滿血硬補、重複 dodge 等。 沒有免疫空砸遮罩——選對傷害型完全交給策略,不由決策層代勞。

改結構前必讀 — 被架構硬保證的不變量

  • 免疫沒有手寫特徵,只有一條學習通路。 抗性/免疫從 obs(I_DESC_RESIST)→ entity_mlp → ent_emb → sk_ent_ctx 注意力 →(skill / entity 頭)。決策層也不再有免疫空砸遮罩。 要判斷模型有沒有真的會讀免疫,只能看這條路的行為(如歸零敵抗性欄,看選型是否塌回亂猜)。
  • skill / entity 頭不吃 h,grid 頭吃。 h 對「選招」的 20 槽、對「選目標」某招下的 10 實體都是同一個常數 → 在那兩個 softmax 會被消掉(死權重、零梯度,實測歸零 h 欄選擇差 <1e-7),故移除。grid 頭 保留 h—— query·cell 逐格不同,h 真的影響落點。身分要影響選招得靠 codeword(逐招不同的乘法項)。
  • end_head 刻意不吃 h。 它只讀 end_features + self_threat + self_reach。若你為了「更強」把 h 接進去, 會重新打開「輸棋→梯度漂移→提早結束」那條退化路徑(已量測)。
  • self-indexed 讀取取代全域池化。 位置靠取 slot 0 / 取自己那格進入 h;任何改回 mean(1) / 空間 pool 的動作, 都要先跑位置敏感度診斷。
  • codeword 是加法雙線性項,不是 concat 欄。 它 += 進 skill_logits;因為 h 是每格廣播的常數、 在 softmax 會被消掉,身分訊號必須用這種逐招不同的乘法項才動得了選擇。
